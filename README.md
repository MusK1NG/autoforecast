# AutoForecast · 复购预测自动建模

上传一份订单明细表，系统自动切时间窗口、自动挑选模型、输出一份「该联系哪些客户」的名单，
并算清楚**该联系多少人最划算**。

面向没有数据团队的中小电商：手里有订单表，但没有会建模的人。

> Upload an order-level spreadsheet → the tool cuts time windows, picks the model by
> walk-forward backtest, and returns a ranked contact list with an expected-profit curve.

---

## 它解决什么问题

「未来 90 天谁会再买」是电商最值钱的问题之一，但常规做法有两个坑：

1. **用交叉验证选模型**。五折都在同一时期里随机切，看不见「时期会变」这回事。
   在一份真实数据上实测：交叉验证挑出的冠军，到下一个时间窗口里排名垫底。
2. **只给分数，不给动作**。模型输出 0~1 的概率，业务方不知道要联系几个人、值不值得做。

这个工具对这两个坑都有明确处理，见下面的「三个技术选择」。

---

## 实测结果

数据集：UCI Online Retail II（英国批发商 2009-12 ~ 2011-12，1,067,371 行原始明细，
清洗后 805,549 行 / 5,878 个客户）。

切成 3 个时间窗口滚动回测，每个窗口「用过去训练、用接下来的 90 天考试」：

| 模型 | 2011-06-12 | 2011-07-27 | 2011-09-10 | 平均 AUC |
|---|---|---|---|---|
| RandomForest | 0.8303 | 0.8257 | 0.8031 | **0.8197** |
| LogisticRegression | 0.8211 | 0.8174 | 0.7966 | 0.8117 |
| Ridge | 0.8176 | 0.8144 | 0.7951 | 0.8091 |

三个窗口的排名完全一致，没有一次翻盘。这是「自动选模型可行」的依据。

最后一个窗口（5,281 人，其中 2,292 人真的复购，占 43.4%）上的实测命中曲线：

| 名单长度（占客户比例） | 真实命中率 |
|---|---|
| 前 8.5% | 0.920 |
| 前 16.9% | 0.873 |
| 前 33.9% | 0.750 |
| 前 50.8% | 0.649 |
| 全选 | 0.434 |

按联系成本 50 元 / 复购毛利 200 元算：最优联系 3,394 人，预计命中 1,979 人，
净收益 226,085 元，而随机联系只有 43.4% 命中率。

## 三个技术选择（也是这个项目的讲点）

### 1. 自动选模型用滚动回测，不用交叉验证

所有 AutoML 库（PyCaret / auto-sklearn / FLAML）都用 CV 分数挑模型。在一份教学数据
（classicmodels，122 个客户、31 个复购人）上实测过：

- 单树 CV 冠军 0.798 → 测试 AUC 0.586
- 森林 CV 冠军 0.867 → 测试 AUC 0.570，是全部模型里最低的
- XGB CV 冠军 0.823 → 测试 AUC 0.602

CV 冠军三次都在测试窗口垫底。原因很简单：五折都在同一段时间里切，学不到时期切换。

这里改成 walk-forward：把时间往后挪，用过去考未来。换到真实数据上，三个窗口的模型
排名完全一致——这才是可以拿来自动化选择的标准。

### 2. 时间窗口切分防泄漏

一行 = 一个客户。特征只看 cutoff 之前，标签看 cutoff 之后 90 天。

    特征窗：[数据开始, cutoff]
    标签窗：(cutoff, cutoff + 90 天]

预测时特征窗放到「数据最后一天」，模型只从最后一个有标签的窗口训练。
窗口是算出来的，不是手写的：cutoff = max_date − 90 天，回测窗口按 45 天往后挪。

### 3. 命中率来自实测曲线，不是拍的

「建议联系多少人」不能拿平均复购率乘一下就算了。这里用最后一个回测窗口上**真实发生
的结果**画出 top-N 命中曲线，再按名单长度的相对分位迁移到本次名单。

### 4. 新客隔离

预测集比训练集多出 597 人（5,878 vs 5,281）——这批人是在最近 90 天才第一次出现的，
模型没见过他们，分数没有意义。系统把他们标成 `is_new=1`、排到名单最后、
并从经济测算里剔除。

## 经济决策：系统只介绍，不替你决定

网页第 4 节先问「你这次的目的」，再给出一个参考名单长度，滑块仍可自己拖：

| 目的 | 你要填什么 | 系统回答什么 |
|---|---|---|
| 净收益最大 | 只有 C / V | 净收益曲线上的最高点在哪 |
| 控制预算 | 这次最多花多少钱 | 预算内最多能联系多少人、预计命中多少 |
| 覆盖一定比例 | 想覆盖百分之多少会复购的人 | 需要联系多少人，命中率是多少 |

同一份预测分数、同一套 C/V，只是目的不同（示例数据 600 客户，C=50 / V=200）：

| 目的 | 联系人数 | 命中率 | 覆盖会复购客户 | 净收益 |
|---|---|---|---|---|
| 净收益最大 | 319 | 0.637 | 88.4% | 24,696 元 |
| 预算 10,000 元 | 199 | 0.746 | 64.5% | 19,740 元 |
| 覆盖 80% 会复购 | 272 | 0.678 | 80.1% | 23,260 元 |

名单长度若算出来是亏的（命中率低于门槛 C/V），界面直接给出警告 —— 比如把 C 调到 150、
仍想覆盖 80%，就需要 272 人、命中率 67.8% < 0.75，净收益 −3,940 元。

## 使用

### 网页

```bash
pip install -r requirements.txt
streamlit run app.py
```

打开 http://localhost:8501，上传订单表。

### 命令行

```bash
python run.py data/online_retail_II.xlsx --top 300 --horizon 90
```

输出 `output/forecast_list.csv`（名单）和 `output/forecast_list_model_scores.csv`（模型成绩）。

### 数据要求

最少两列：**客户编号**、**下单日期**。金额给一列，或者给「数量 + 单价」两列。
其余列可有可无。列名不用改，系统按列名 + 统计特征自动识别，认错了网页上可以手动改。

列识别只在前 5,000 行上判断（全量 106 万行逐行解析日期要几分钟）。

## 局限（已知，别当没有）

1. **模型基本在学「最近买过的人还会买」**。top 8.5% 的命中率能到 92%，但这批人本来就会买，
   给他们发营销等于给马上要下单的人打折。真正难也更有价值的问题是「沉默客户召回 / 流失预警」，
   这是下一步要做的方向。
2. **只有三个回测窗口**，且都在同一份数据的后半段。数据更短（不足 270 天）时切不出窗口，
   工具会直接报错退出。
3. **列识别靠表头正则**，中文表头或奇怪命名会认错，需要人工在下拉框里改。
4. **没有做校准**（Platt / isotonic），输出的是排序分数，不是严格意义上的购买概率。
5. 经济测算里的 C（触达成本）和 V（复购毛利）必须由使用者填，样本数据里没有真值。
